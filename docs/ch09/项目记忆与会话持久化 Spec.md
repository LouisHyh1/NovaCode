# 项目记忆与会话持久化 Spec

## 背景与问题

NovaCode 当前只能维护进程内对话。ch08 已能在上下文接近上限时压缩历史并落盘大型工具结果，但进程退出后，项目约定、对话进度和长期有效的信息仍无法在新会话中复用。

真实编码任务通常跨越多次启动：用户希望 NovaCode 每次进入项目时都遵循相同规范，能够恢复某次工作的完整消息与工具调用边界，并逐步积累稳定的用户偏好、纠正反馈、项目知识和参考资料。缺少统一持久化模型会导致重复解释、恢复出错、上下文污染，以及记忆文件无限增长。

本章定义四项相互配合但边界清晰的能力：项目指令为当前请求提供静态约束；JSONL 会话存档保存可恢复的工作历史；自动记忆提取跨会话仍有价值的信息；记忆治理定期合并、修正和淘汰记忆。所有能力均复用 NovaCode 现有 prompt 组装、Agent Loop 和 ch08 上下文压缩机制。

## 目标

- **G1**：新会话从四个固定位置加载项目指令，按明确优先级拼接，并安全展开文件引用。
- **G2**：每个会话实时追加到单个 JSONL 文件，保证磁盘记录先于内存状态，并能从损坏或中断的存档恢复到最后一个完整工具调用边界。
- **G3**：用户可以恢复历史会话；长时间未活动的上下文会获得提醒，过期存档在后台清理。
- **G4**：每轮最终回复后异步尝试提取长期记忆，按四种类型写入固定层级，并通过轻量索引按需读取正文。
- **G5**：记忆治理在严格门控和受限权限下后台运行，不阻塞主会话，并能安全处理并发、失败和陈旧锁。
- **G6**：项目指令和长期记忆通过现有 prompt 可选模块注入，不复制上下文压缩、文件工具或 Agent 主循环。

## 功能需求

### 项目指令文件

- **F1**：NovaCode 启动时按以下由低到高的优先级检查四个位置；文件不存在时跳过：
  1. `~/.novacode/NOVACODE.md`；
  2. `<project_root>/NOVACODE.md`；
  3. `<project_root>/.novacode/NOVACODE.md`；
  4. `<project_root>/NOVACODE.local.md`。
- **F2**：已加载内容按 F1 的顺序拼接，高优先级内容排在后面；相邻的非空层之间插入独占行 `---`，使来源边界可见且后置内容可以覆盖前置约束。
- **F3**：指令文件仅将匹配独占行 `@<relative_path>` 的内容识别为引用。路径相对于声明该引用的文件所在目录解析；行内出现的 `@` 文本保持原样。
- **F4**：引用可以递归展开，最大深度为 5 层。根指令文件不计入引用深度，展开第 5 层文件后不再继续展开其中的引用，并记录可诊断警告。
- **F5**：引用展开使用“当前访问链”检测环路。同一文件在不同分支可被正常引用；仅当规范化绝对路径已出现在当前递归链中时跳过该引用并记录警告。
- **F6**：来自用户级指令的引用必须位于 `~/.novacode/` 内；来自其余三处指令的引用必须位于 `<project_root>` 内。边界检查使用规范化后的真实路径，拒绝 `..`、符号链接或等价路径造成的越界访问。
- **F7**：引用目标缺失或不可读时跳过并记录诊断，不阻止其余内容加载；空文件产生空内容；检测到二进制内容时拒绝注入。单个引用失败不得让整个指令加载失败。
- **F8**：拼接结果作为当前 prompt 的 `自定义指令` 可选模块。结果为空时省略该模块；非空结果在进程启动阶段加载并缓存，本章不监听运行期文件变化。

### 会话持久化

- **F9**：每个新会话生成 `YYYYMMDD-HHMMSS-xxxx` 格式的 session ID，其中时间部分使用本地启动时间，`xxxx` 为 4 位随机十六进制后缀。消息存档路径为 `.novacode/sessions/<YYYYMMDD-HHMMSS-xxxx>.jsonl`。
- **F10**：ch08 工具结果继续写入 `.novacode/sessions/<session_id>/tool-results/`。JSONL 文件名中的 ID 与工具结果目录中的 `<session_id>` 必须相同，但前者是文件、后者是目录，不得把消息文件放入工具结果目录。
- **F11**：一个会话只使用一个 JSONL 消息文件。每条消息记录至少包含 `type`、`role`、`ts`；按消息形态包含 `content`、`tool_calls` 或 `tool_results`；首条消息额外记录 `model`。工具调用和工具结果保留既有 ID、名称、参数、结果内容及错误状态，以便恢复时配对。
- **F12**：新增消息必须先完成序列化和持久化，再更新进程内 `Conversation`。持久化失败时记录错误且不得让内存历史领先于磁盘历史；调用方获得可处理的失败结果。
- **F13**：会话写入器只以追加模式写入，不重写已有记录；并发 append 由单会话锁串行化。每次追加完整 JSON 行后执行 `flush` 和 `fsync`，退出或切换会话时关闭文件句柄。
- **F14**：ch08 生成压缩后的替换历史后，写入器在同一 JSONL 文件中执行带唯一事务 ID 的追加式压缩事务：先追加声明替换记录数和内容摘要的 `compact_begin`，再追加该事务的完整替换历史，最后追加引用同一事务 ID、记录数和摘要的 `compact_commit`；各记录沿用 F13 的持久化保证。只有 `compact_commit` 完成 `fsync` 后才调用 `Conversation.replace_history()`。恢复器只采用 begin、完整替换历史和 commit 均有效，且事务 ID、记录数和摘要一致的最后一个已提交压缩事务；缺少 commit、记录损坏或替换历史不完整的事务整体忽略，并继续使用该事务开始前的完整历史，不另建平行压缩格式。

### 会话恢复与清理

- **F15**：会话列表扫描 `.novacode/sessions/*.jsonl`，以 JSONL 内最后一条有效记录的活动时间为准倒序排列；无有效消息的文件不作为可恢复会话。列表至少展示 session ID、首条用户消息摘要、模型、最后活动时间和文件大小。
- **F16**：恢复时逐行解析 JSONL，跳过无法解析或字段不合法的行并记录诊断。单个坏行不得阻止读取后续有效记录；最后一行因崩溃而截断时按坏行处理。
- **F17**：恢复器校验 assistant `tool_calls` 与后续 `tool_results` 的 ID 和顺序，只保留最后一个完整工具调用链边界。assistant 调用未闭合、部分返回或 ID/顺序不匹配时，从发起该链的 assistant 消息之前截断；`tool_results` 没有对应的在途 assistant 调用时，从该孤立结果记录之前截断。两类截断都保留此前最后一个完整边界，避免模型接收无法继续的工具状态。
- **F18**：恢复后的 token 估算超过当前上下文安全阈值时，复用 ch08 压缩流程和 `Conversation.replace_history()`，压缩成功后再开放下一轮输入；压缩失败则给出可见错误并保持原会话不变。
- **F19**：恢复成功后使用被恢复的 session ID 重新打开对应 JSONL 追加器和工具结果目录，后续消息继续写入原会话。被恢复前临时创建的新会话存档不自动删除。
- **F20**：若恢复会话的最后活动时间距当前超过 24 小时，NovaCode 在恢复历史末尾注入一条仅用于当前上下文的系统提醒，说明历史信息可能过期并建议重新读取易变资料；提醒本身不伪装成用户原始消息。
- **F21**：NovaCode 在后台清理最后活动时间超过 30 天的会话。最后活动时间从 JSONL 有效记录获取；清理同一 ID 的 JSONL 文件及工具结果目录。单项清理失败只记录日志，不影响其他会话，也不阻塞启动或交互。

### 自动记忆

- **F22**：记忆类型和落盘层级固定如下，不允许模型自行改变路由：
  - `user`、`feedback` 写入 `~/.novacode/memory/`；
  - `project`、`reference` 写入 `<project_root>/.novacode/memory/`。
- **F23**：每条记忆保存为独立 Markdown 文件，并包含 YAML frontmatter。frontmatter 至少包含稳定 ID、`type`、`title`、`created` 和 `updated`；正文使用可独立理解的陈述，时间敏感信息优先记录绝对日期。
- **F24**：每个 memory 目录各维护一个 `MEMORY.md`。每个索引项必须包含类型、标题、简短说明及指向对应 Markdown 文件的可点击相对链接；索引不内嵌记忆正文。
- **F25**：单个 `MEMORY.md` 同时满足最多 200 行且文件大小不超过 25KB。每次普通提取提交前必须在锁内构造候选索引，按 delete、update/merge、create 的顺序逐项应用；任一操作会使候选索引超过任一限制时，拒绝该操作并保留它执行前的记忆文件和索引，记录结构化诊断。系统不得先落盘超限索引，也不得等待后续治理修剪。prompt 只注入索引；需要详情时，模型通过现有文件工具按相对链接读取独立记忆文件。
- **F26**：每轮 Agent Loop 产生不含待执行工具调用的最终回复后，都向当前项目上下文的单消费者提取队列异步提交一次任务。入队不得延迟最终回复、阻塞下一轮输入或修改本轮会话历史；队列按提交顺序执行任务，防止多轮提取并发使用陈旧索引。
- **F27**：提取请求包含最近一轮用户消息与最终回复、两级现有记忆清单、固定类型路由和明确的 `create`、`update`、`delete`、`no-op` 操作约束；请求不携带任何工具定义，模型不得发起工具调用。
- **F28**：提取模型返回结构化操作。执行器逐项校验操作、类型、目标层级、文件名和目录边界；`no-op` 不产生文件变更，非法或越界操作被拒绝并记录日志。
- **F29**：是否值得保存、是否与现有记忆重复、是否存在冲突以及应创建、合并、更新或删除，由 LLM 结合完整索引判断。执行器不增加 embedding 或相似度搜索作为第二套去重机制。
- **F30**：每个提取任务必须在前一任务提交或失败收尾后，以固定顺序获取它可访问的两级 memory 目录锁；获取后重新读取最新索引，并持锁依次完成推理、操作校验、F25 候选限额验证和提交。“读取最新索引—推理—校验—提交”整个流程按 F26 串行，不得仅锁最终写入阶段；治理写入必须使用同一目录锁。成功后刷新后续任务使用的索引快照；模型错误、解析错误或写入错误只记录日志，随后释放全部锁和队列执行权，不中断主会话。

### 记忆治理

- **F31**：治理负责合并重复记忆、删除过时内容、修正明确矛盾、把相对日期改写为绝对日期，并修剪 `MEMORY.md` 使其满足 F25；治理不得凭空扩展未经会话或现有记忆支持的事实。
- **F32**：治理只在以下五道门控全部通过时启动：memory 目录存在；距上次成功治理至少 24 小时；距上次扫描至少 10 分钟；累计可用会话至少 5 个；成功获取 `.consolidate-lock`。
- **F33**：每次检查都更新时间独立的“上次扫描”状态，以实现 10 分钟节流；未通过任一门控时直接返回，不创建后台治理任务。
- **F34**：`.consolidate-lock` 保存持有者 PID，并使用 mtime 表示最近一次成功治理时间。锁回收优先以 PID 状态判断：PID 确认存活时，无论锁龄是否超过 1 小时都不得抢占；PID 确认不存在时可原子回收；只有当前平台无法可靠判断 PID 状态时，才以锁龄超过 1 小时作为兜底回收条件，未超过 1 小时则保留。
- **F35**：获取锁后先保存原 mtime。治理成功时更新 mtime 并释放运行态占用；治理失败、取消或异常退出时恢复原 mtime，使失败任务不会错误推迟下一次合格治理。
- **F36**：实际治理由后台受限子 Agent 执行。它只能读取会话存档和两级记忆资料，写入范围只限本次治理对应的 memory 目录；不得调用任意 shell、修改项目源码或访问边界外路径。
- **F37**：治理任务不阻塞启动、Agent Loop 或用户输入。任务结束后向主会话发送一条简短通知，包含完成状态和 create/update/delete 数量；失败通知不得暴露敏感记忆正文。

### 集成与生命周期

- **F38**：当前 prompt 保留独立的 `自定义指令` 和 `长期记忆` 可选模块。前者使用 F8 的拼接结果，后者按“用户级索引在前、项目级索引在后”的低到高优先级拼接；任一内容为空时省略对应模块。
- **F39**：启动顺序为：确定项目根和 session ID、加载项目指令、初始化记忆索引、创建会话写入器、组装 prompt、启动会话清理与治理懒检查。后台任务失败不得阻断 TUI 进入可交互状态。
- **F40**：每轮生命周期为：持久化用户消息后更新内存、运行 Agent Loop、逐条持久化 assistant 与工具消息后更新内存、发送最终回复、调度异步记忆提取。任何阶段不得出现内存已接受而磁盘尚未接受同一消息的可观察状态。
- **F41**：切换或退出会话时停止向旧写入器提交新消息，等待已经进入临界区的 append 完成，再关闭句柄；未完成的记忆提取和治理任务按可控方式取消或收尾，不得写到错误项目或会话。
- **F42**：新增能力复用现有 `NovaCodeApp`、prompt 模块槽位、文件工具、`Conversation.replace_history()` 和 `src/novacode/compact/`。未启用或无数据时，NovaCode 保持 ch08 的现有交互行为。

## 非功能需求

- **N1（可靠性）**：已经返回成功的消息 append 必须可在进程重启后读取；损坏记录、单个不可读指令、单条清理失败及后台记忆错误均被隔离。
- **N2（并发安全）**：同一会话的消息追加保持顺序；同一 memory 目录的提取与治理写入互斥；会话切换不得造成跨 session ID 写入。
- **N3（安全）**：所有引用、记忆操作和治理写入都在规范化路径后执行边界校验；二进制指令、越界路径、非法操作和受限子 Agent 的越权请求必须被拒绝并留下不含敏感正文的诊断。
- **N4（性能）**：指令和索引只在启动或成功更新后重载；会话扫描按需读取有效记录，不加载工具结果正文；提取、清理和治理均在后台执行，主交互不等待其完成。
- **N5（兼容性）**：项目没有指令、memory 目录或历史会话时仍可正常启动；新增 prompt 参数、会话回调和后台能力均为可选，不改变未启用路径的既有行为。
- **N6（可测试性与可观测性）**：指令展开、JSONL 编解码、完整工具链截断、记忆路由、索引限制和治理门控可在无真实 provider、无 TUI 的条件下测试；所有降级路径提供结构化日志或用户可见通知。

## 不做的事

- 不引入 SQLite 或其他会话数据库。
- 不引入向量数据库、embedding、相似度搜索或 RAG 记忆检索。
- 不实现完整 Slash Command 框架；历史会话入口只承担本章所需的恢复能力。
- 不做云端同步、团队共享或跨设备记忆合并。
- 不自动恢复最近会话；启动默认创建新会话，恢复必须由用户主动选择。
- 不合并两个独立会话，也不为旧存档设计批量迁移器。
- 不加载全部记忆正文到 prompt，不提供记忆全文搜索。
- 不监听指令文件的运行时变化。
- 不复制 ch08 的上下文压缩或工具结果落盘实现。

## 验收标准

### 项目指令

- **AC1（四层优先级）**：四个位置分别写入可区分内容并启动 NovaCode；`自定义指令` 按用户级、项目根、项目私有目录、本地覆盖的顺序出现，高优先级在后，非空层之间存在独占行 `---`。
- **AC2（缺失容错）**：仅创建其中一个 `NOVACODE.md`，其余位置缺失；启动成功且模块只包含已有文件内容。创建空文件或不可读引用时，其余内容仍可加载。
- **AC3（引用语法与深度）**：独占行 `@rules/style.md` 被文件内容替换，段落中的同名文本保持原样；构造 6 层引用链时只展开前 5 层并产生深度诊断。
- **AC4（环路与复用）**：A 引用 B、B 引用 A 时第二次访问 A 被跳过；两个互不嵌套的分支分别引用同一文件时，两处均能正常展开。
- **AC5（引用边界与二进制）**：分别使用 `..` 和符号链接尝试越过用户目录或项目根，并引用含空字节文件；三种目标均不进入 prompt，且各自产生对应诊断。

### 会话持久化与恢复

- **AC6（路径关联）**：启动新会话后生成形如 `20260716-103000-a1b2` 的 ID；消息位于 `.novacode/sessions/20260716-103000-a1b2.jsonl`，工具结果位于 `.novacode/sessions/20260716-103000-a1b2/tool-results/`。
- **AC7（先盘后内存）**：用可观察的 mock 写入器发送 user、assistant、tool 消息；每次内存变更前都已完成对应 JSON 行的 append、`flush` 和 `fsync`。模拟写入失败时，该消息不进入内存。
- **AC8（追加与崩溃恢复）**：连续写入多条消息并截断最后一行后重启；之前的 JSON 行保持不变且可恢复，截断行被跳过，随后仍可向同一文件追加。
- **AC9（工具链截断）**：分别构造完整调用链、缺少结果的调用、多工具仅部分返回、ID/顺序不匹配和没有在途 assistant 调用的孤立结果；完整链全部保留，缺少结果、部分返回和 ID/顺序不匹配均从发起该链的 assistant 消息之前截断，孤立结果从其自身记录之前截断，且两类情况都保留此前最后一个完整边界。
- **AC10（压缩复用）**：触发 ch08 压缩后，JSONL 依次出现同事务 ID 的 `compact_begin`、完整替换历史和 `compact_commit`，且内存历史只在 commit 完成 `fsync` 后替换。分别在 begin 后、替换历史写入一部分后模拟崩溃，恢复器均忽略未提交事务并保留事务前完整历史；仅完整提交事务被恢复采用。构造超阈值存档时先经同一压缩流程再开放输入。
- **AC11（会话列表与续写）**：准备多个 JSONL，其文件 mtime 与记录活动时间顺序不同；列表按有效记录时间排序。选择某项后使用原 session ID，新增消息写回原 JSONL 和对应工具目录。
- **AC12（24 小时提醒）**：恢复最后活动时间分别为 23 小时 59 分和 24 小时 1 分的会话；前者不注入提醒，后者在当前上下文末尾出现过期提醒，原 JSONL 历史不被伪造修改。
- **AC13（30 天清理）**：准备最后活动时间分别为 29 天 23 小时和 30 天 1 分的会话；后台清理仅删除后者的 JSONL 与同 ID 工具结果目录，且清理期间主界面可继续响应。

### 自动记忆

- **AC14（四类路由）**：让提取模型分别返回 `user`、`feedback`、`project`、`reference` 的 create 操作；前两类只写入用户级 memory 目录，后两类只写入项目级 memory 目录。
- **AC15（文件与相对索引）**：创建一条记忆后，得到含规定 frontmatter 的独立 Markdown 文件；对应 `MEMORY.md` 包含可点击相对链接、类型、标题和摘要，且未嵌入完整正文。
- **AC16（每轮提取与串行化）**：连续完成三轮没有待执行工具调用的最终回复；每轮都立即入队一次提取任务，最终回复和下一轮输入均不等待任务完成，提取请求的工具定义为空。延迟第一项任务并快速完成后两轮时，后续任务不并发推理，而是在前一项提交或失败收尾后按顺序启动，并读取包含前一项结果的最新两级索引。
- **AC17（操作与去重）**：分别返回合法的 create、update、delete 和 no-op，验证前三种操作正确更新文件与索引且 no-op 不产生变更。预置已有记忆后，把语义重复内容作为最近一轮对话交给提取模型；验证模型在队列临界区内读取最新完整索引，并返回 no-op 或指向既有条目的 update（合并），最终不创建新文件。另行返回类型或目标层级非法的 create 以及越界文件名，验证执行器拒绝这些操作且主会话继续运行。
- **AC18（索引双限制）**：分别让 create 导致第 201 行和超过 25KB；两项操作都在提交前被拒绝，现有记忆文件与 `MEMORY.md` 保持原样并产生结构化诊断，且不调度治理兜底。再通过 delete 或 update/merge 同步释放容量后执行 create，只有候选索引同时不超过 200 行和 25KB 时才提交；prompt 的 `长期记忆` 始终只含合规索引及相对链接。

### 记忆治理

- **AC19（五道门控）**：对“目录不存在、未满 24 小时、未满 10 分钟、少于 5 个会话、锁获取失败”逐一构造场景；任一条件不满足都不启动治理，五项全部满足时只启动一个后台任务。
- **AC20（锁回收）**：分别创建活跃 PID 且超过 1 小时、死 PID、PID 状态未知且未满 1 小时、PID 状态未知且超过 1 小时的锁；活跃 PID 锁始终保留，死 PID 锁和状态未知但超时的锁可原子回收，状态未知且未超时的锁保留。并发两个检查时最多一个获得锁。
- **AC21（失败恢复）**：记录治理前锁 mtime 并模拟成功、异常和取消；成功后 mtime 更新，异常与取消后恢复旧 mtime，使后续检查仍按上次成功时间判断。
- **AC22（受限写入）**：治理子 Agent 可读取会话和记忆、可修改目标 memory 目录；尝试执行 shell、修改源码或写到边界外时被拒绝，已允许的记忆变更不受影响。
- **AC23（通知与非阻塞）**：治理运行期间连续发送消息，主流程正常响应；治理完成或失败后只收到一条简短状态与操作计数通知，通知不包含记忆正文。

### 集成与生命周期

- **AC24（prompt 模块）**：分别传入空和非空的指令、记忆索引；非空内容进入对应的 `自定义指令`、`长期记忆` 模块，空内容使模块省略，项目级记忆索引排在用户级索引之后。
- **AC25（启动降级）**：在无指令、无 memory 目录、无历史会话以及后台清理或治理抛错的场景启动；`NovaCodeApp` 均可进入交互状态，错误被隔离并记录。
- **AC26（切换与退出）**：在 append 进行中切换会话或退出；旧写入完成后句柄关闭，没有消息跨 session ID，后台任务不会写入已切换到的错误项目。
- **AC27（静态边界）**：检查实现依赖和文档范围；会话、记忆和治理能力未引入 SQLite、向量数据库、embedding、相似度搜索或完整 Slash Command 框架，并继续复用 ch08 压缩与工具结果机制。
