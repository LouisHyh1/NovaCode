# 评测执行、冻结与分析协议

协议版本：规划v1，2026-10-09。对应 [proposal.md](proposal.md)、[design.md](design.md)、[specs](specs/) 和 [task-catalog.md](task-catalog.md)。本文件规定未来执行行为；尚未形成可执行冻结清单、已入库资产或实测结果，数值预算等字段须在对应阶段取得证据后填写。

## 1. 对象与成功口径

主集评估单主Agent在Python、WSL/Linux任务环境中的编程行为，真实模型执行请求，自动化入口复用产品主循环，外部独立判题。TUI、权限、Session、长期记忆、多Agent、Windows兼容性另作专项，不进入432个主集计划行。现有Fake或脚本化Provider测试证明运行机制，不提供真实模型任务成功率。

一个Evaluation Task含单次请求或自建题的固定多轮脚本；一次Evaluation Run从全新条件执行整个合同，可以包含多个Agent Run，费用合计。无人辅助表示人不在运行中临时加提示，Agent可在预算内测试、修改和恢复。Live保持官方单次issue rollout，不套用多轮专项协议。

严格成功要求正常完成、独立验收全部通过、修改范围合法和必要清理成功；终止状态、验收及清理分别保存。部分完成为诊断。Live另保存官方resolved口径：若超时后的补丁通过官方测试，可同时记录resolved=true和strict_success=false，不能混淆两个指标。

## 2. 题库身份与入库

目标为24开发题和48冻结题，Live与专项等量，具体配额见任务目录。Live候选数据身份为 `SWE-bench-Live/SWE-bench-Live`、`verified`、revision `b51a86422e10cfd403beb4773e5a2947953e36ec`。这是观察到的元数据身份；实际入库须从指定revision提取完整数据并核对ID、base_commit及字段指纹。verified是LLM筛选，不表述成人工验证。[官方数据卡](https://huggingface.co/datasets/SWE-bench-Live/SWE-bench-Live)

Live资格筛选顺序为：固定完整版本；定义CPU、依赖、网络与自动判题资格；审查问题和家族；核验镜像及独立Agent环境；确认原始代码在目标行为验收失败且相关原有行为有效；参考补丁连续三次通过；保存资源峰值、时间和日志指纹。随后按事前记录的仓库上限、复杂度层、种子和替补规则选择任务。排除和替换须可追溯，不依据NovaCode正式成败。[官方有效性核验](https://github.com/microsoft/SWE-bench-Live/blob/main/evaluation/README.md#run-gold-patch)

任务目录的12条Live来自初次查看前100行，仅用于核对内容，不能直接成为最终代表性样本。正式从完整固定题池分层。自建题核验正确实现、缺陷实现、错误答案、范围检查和注入可重复性；测试补充题要求新增测试正常收集、在正确实现通过并检出全部目标缺陷，导入失败与跳过不算检错。

按任务ID、issue、修复来源及受控缺陷家族分割。改写请求、改参数、改文件名或同源缺陷不能跨开发和冻结；官方split名称不能直接代替本项目划分。共享通用构建器可以保留，但被测问题和业务事实必须独立。家族映射、候选池及抽样过程在正式前保存。

Live运行只提供原始problem_statement、任务镜像与通用或仓库级指令，不提供patch、test_patch、hints、目标测试名单或最终验收反馈。隐藏验收在结束后的独立干净环境执行，不能据此修改同一次提交。[官方输入协议](https://github.com/microsoft/SWE-bench-Live#-evaluation)

当前源码Anthropic适配器设置max_tokens=4096，只在无工具历史时按thinking配置发送budget_tokens=2048；它们是现状，不是模型能力保证。正式冻结相同适配规则和常量，逐请求记录实际thinking是否发送；历史变化可能影响触发，结论解释为机制总效应，不能只归因于Schema字节减少，也不能为某组单改规则。

SDK内部重试可能把一个Provider调用扩成多个HTTP尝试。首版评测将SDK自动重试设为0，普通产品默认不改，tmux评测使用同一配置；Agent显式上下文恢复和摘要重试仍逐请求记录。若保留SDK重试，则需记录每次HTTP尝试和预算，否则不能称账本完整。[Anthropic SDK重试](https://github.com/anthropics/anthropic-sdk-python#retries)

缺失必要参数不是可执行默认值。规划可保留待测量数值，但pilot须先有有限临时上限，freeze须校验所有必要字段，正式run须校验身份和剩余总预算。模型不支持seed或某采样参数时记录unsupported，不伪造确定性。

## 4. 三配置与运行计划

| config_id | 压缩 | Schema | 比较含义 |
|---|---|---|---|
| full | Layer1与Layer2开启 | deferred | 完整方案 |
| no-compression | 全关，含自动/紧急/手动/恢复 | deferred | full减去该组：按需曝光开启时压缩总效应 |
| eager-schema | 开启 | eager | full减去该组：压缩开启时按需曝光总效应 |

三组保留相同工具能力、发现入口、权限、服务连接、业务数据、工具输出边界、只读并行、模型适配规则、初始输入和预算。差异只有两项明示策略；双方初始输入合法，运行中超限保留为结果，不偷偷摘要或删除历史。没有双关组，不能估计交互或两项独立贡献之和。

48任务×3配置×3独立重复=432个原计划行，每配置144次、每来源每配置72次。键含campaign_id、task_id、config_id、repeat_id；配对键为task_id和repeat_id。全部初始PLANNED，不创建伪结果；补跑使用新run_id及retry_of，不占用已有结果的计划键。

每题每重复为三配置配对块，以固定种子均衡六种配置顺序并写入计划。正式主耗时评测任务并发度1，本地资源相同。独立运行重建代码、对话、Session和曝光状态；远端模型缓存未必清空，记录缓存用量及请求时间，不加入随机提示伪造冷缓存。

## 5. 预算与停止

任务的预算类别基于主类型、逻辑难度和压力标签事前确定。开发先导测量三组成本与失败，形成同题共享上限；不要求实际消耗相同，因为减少消耗本身就是待测效果。主请求、摘要、显式重试及全部脚本阶段均计量，发现、失败、拒绝均计工具请求。

每次模型请求前检查已知累计与输入估计/输出上限的保留余量；估计只作准入保护。未知失败usage标UNKNOWN并停止追加调用；单请求实际超出保留估计时保留已知耗用和越限，不隐藏、不放宽某组。Token上限与调用上限分别生效。

截止时间从该次应用初始化起计，到期停止新增工作、取消Agent和所属工具，在相同冻结清理宽限内完成收尾。端到端含初始化、执行和清理；镜像准备、下载、独立判题单列。残留进程或清理超时使严格成功为false，独立判题不与仍能修改产物的进程并发。

状态序列为PLANNED、PREFLIGHT、RUNNING、STOPPING、GRADING、RECORDED。前置失败保留未开始及环境原因，不产生虚假Agent失败；RUNNING后完成、超时、预算耗尽、取消、Provider错误、上下文错误、基础设施或清理错误均保留。现有补丁可独立判题作诊断，不能覆盖终止原因。

已开始原计划不重置。补跑另记恢复运行，原结果保留且不取最好一次；代码、预算或合同修订形成新campaign，不能混用冻结身份。主报告含所有已开始原计划并按故障分解，基础设施异常影响比较时注明。

| Run | 唯一身份、初始指纹、UTC与单调时间、终止、严格成功、验收、清理和完成度 |
| Provider | request_id、角色、重试关联、输入与Schema指纹、实际参数、起止、状态、原始用量/归一化/完整性 |
| 工具 | call_id、顺序、名称、完整脱敏参数、起止、授权/执行/错误、结果引用和发现标记 |
| 机制 | Layer1实际变化、Layer2请求与接受、触发入口、超限恢复、目录和Schema集合变化 |
| 判题与产物 | 判题版本与每项结果、Live resolved、范围与清理、最终回答、固定base完整补丁含新增文件、轨迹及输出指纹 |

Provider账本是Token唯一累加来源，不再叠加主Event.usage。按实测协议归一化：input不含缓存读写则加入，缓存已为input子集则不再加入，output里的推理子集同理；兼容端点不凭协议名推断。未知不是0，已知部分是下界，上下文估计另列。无实际价格证据不填金额0冒充免费。

工具总数按每个请求开始计一次，另列实际执行、成功、拒绝、发现和错误数。单调时钟用于应用初始化到关闭完成的主端到端，UTC用于审计；环境准备、判题和总墙钟分列。脱敏去除认证秘密，保留业务内容和必要参数，原始轨迹增量写入，不因报告重生成被覆盖。

补丁基于固定base，不只取当前HEAD差异；包含Agent已提交和未跟踪新文件，排除运行时状态。提取只在隔离任务环境进行，不改操作者索引；结束后用独立干净副本判题。

## 7. 分析规则

完整campaign严格成功率为严格成功原计划数/该配置144次，分来源各72次。每任务重复数相同时，与先取三次均值再平均一致。Live另报官方resolved率与strict差异，自建不称官方SWE成绩；内部综合值如展示，采用Live与专项等权宏平均并明示口径。

未完成时展示计划、已开始、完成、成功、失败和未开始数量，只报告已开始样本成功率，不能称144次完成。可给计划成功率下界成功数/144、上界(成功数＋未开始数)/144，明确它们是未完成范围，不把未开始归因为Agent失败。

工具、成本、耗时保留正常和失败运行，报告均值、中位数、p90与样本数；p90使用nearest-rank即排序后ceil(0.9N)位置。Token缺失时报告下界、完整测量比例和各组缺失分布；精确成本只在共同完整样本配对并注明缺失偏差，不能推广为全部任务的确定收益。

两项主要效果为full相对各消融的严格成功率差，单位百分点；先对每题每配置三次结果取均值，再对同题求差。Token、时间和工具次数为辅助效果，同样按每题三次均值配对并保留原分布。不得只比较成功样本而隐藏失败代价。

采用95%任务级配对percentile bootstrap、10000次重采样、冻结种子；重采样某任务时同时携带其全部配置和重复。总体、来源和事前压力子集分开分析，少量专项子集明确探索性；三次重复不是三个独立任务。两项主要比较与多个辅助指标均列出，不靠事后选指标宣称显著；不预设提升阈值或非劣界限。

区间只描述所选题库和采样规则下的条件不确定性，任务家族隔离不保证同仓库题目统计独立；报告仓库、家族和任务数量。若全部任务差值相同或样本不足，标记bootstrap退化/不可可靠估计，原点估计仍保留；零宽区间不意味着机制完全等效、成功率确定或结论可普遍推广。

压缩及发现压力子集由合同标签事前确定，包括无触发和失败。实际触发记录检查、卸载、摘要请求/接受、曝光变化和辅助工具使用；按实际触发再分层只作诊断，不能替代预定主比较。结论接受零或负收益，完成条件是有效执行和可复核，不是必须改善。

失败归因依据终止和验收证据，区分行为错误、范围违反、测试不足、工具恢复、上下文、预算、Provider、环境及清理；主因与次因可并存，人工复核保存版本而不改原轨迹。

## 8. 阶段出口与专项

| 出口 | 必需证据 | 缺失时 |
|---|---|---|
| ENV_READY | 容器访问、资源、独立Agent与目标解释器、参考题核验 | 不调用Live模型 |
| CODE_READY | 预算、观测、策略、隔离、相关回归及tmux等价 | 不开始先导campaign |
| DEV_ADMITTED | 12 Live＋12专项有效合同与指纹 | 报缺口，不称24题就绪 |
| PILOT_COMPLETE | 有限预算下真实开发运行、完整性与触发覆盖、修订记录 | 不正式freeze |
| FROZEN_VALID | 48冻结合同、执行参数、家族隔离、432行计划 | 不开始正式模型调用 |
| FORMAL_COMPLETE | 全部432原计划都有不可覆盖的终止与验收记录 | 输出部分报告、保留待运行计划 |
| REPORT_REVIEWED | 分来源、机制覆盖、配对结果、失败证据与结论复核 | 不宣称结果交付完成 |

专项至少覆盖真实tmux普通工具与流式结束、权限拒绝与边界、Session创建/写入/恢复/退出、隔离记忆显式操作与后台关闭、多Agent团队/任务及收尾、Windows本地或已授权CI的锁文件/测试/启动。费用另账，真实模型与Fake证据分开，未取得证据标待验收。
