# 第九阶段真实开发先导与校准

第九阶段 9.1–9.6 达到 `PILOT_COMPLETE`，版本 0.1.34，整体进度 54/71。24 个开发任务各运行三配置一次，形成 72 条原计划真实记录；另有三次 S01 tmux 产品验收、六次校准代表复验与三个公开用量探针。它们分列，不替换原计划，不算 432 次正式实验。第十阶段冻结尚未开始。

## 模型与有限合同

2026-10-12 用户确认沿用 `https://api.deepseek.com/anthropic` 和请求名 `deepseek-v4-flash`，按官方当前映射记录服务身份为 DeepSeek-V4.1-Flash。响应仍返回兼容别名，不能将它当作旧 V4-Flash 或不可变权重版本。应用沿用既有 200,000 Token 窗口，端点文档能力为 1M；三配置相同，未通过缩小窗口制造触发。[端点核验](model-endpoint.json) 与 [官方说明](https://api-docs.deepseek.com/quick_start/pricing/) 可复核。

SDK 0.112.0，零自动重试、90 秒请求超时、输出上限 4096、thinking=true。适配器只在无工具历史时显式发送 thinking；真实响应证明省略后仍有 thinking 块，符合端点默认开启。发送的 budget_tokens=2048 被兼容端点忽略，推理 Token 子计数缺失保持未知，不额外加到输出总量。两次 Anthropic 与一次原生接口的同一公开文本核验缓存独立计数，原始字段见 [探针](usage-probe.json)；该探针关闭 thinking，只核验缓存，不能冒充主集推理轨迹。

原合同普通任务 300 秒、600,000 Token、24 Provider/50 工具请求，单请求预留 100,000；长上下文 420 秒、1,500,000 Token、40/70，单请求预留 240,000；清理均 20 秒。首个模型调用前验证全部数值，先完成 S01/L02 六次代表运行，再显式扩展 66 次。24 题的六种配置顺序各使用四次，任务并发度 1；代码、资产、权限、能力、通用提示和实际策略均有身份或账本。

全部轮次共享 30,000 秒、60,000,000 Token、2,200 Provider/4,200 工具请求总预留。失败和未知用量不退还。六次修订后复验使用新 Campaign，S01 为 200 秒、100,000 Token、12/15、单请求 50,000；S08 沿用长上下文上限，各配置同题一致。最终整次预留 57,920,000 Token、2,103 Provider、4,186 工具、25,530 秒，没有扩大总上限，见 [跨轮账本](shared-budget-audit.json)。预留是准入保护，不能当作实际费用。

## 修订依据与复验

S01 两份真实答案合并两条合法关系路径，旧评分器整份相等比较将其拒绝；解释字段也影响相等。修订只投影合同事实字段，允许同一合法符号集合中的已验证关系组合，至少覆盖一条完整合法路径，未知边仍失败。S02 补充源码确实存在的详细异常类传播路径；未参与路径的 network_error 仍被拒绝。三个回归用例先失败后通过，见 [修订前](regression-red.txt)、[修订后](regression-green.txt)。

12 道专项重新验证正确实现、缺陷、错误答案和范围，在新的 [入库账本](specialty-admission/selection.jsonl) 关联新合同。所有公开输入、初始文件和环境按字节不变，见 [不变性审计](public-input-invariance.json)；旧资产和判题源码保存在 [历史原件](assets-before-calibration.tar.gz)。39 份首轮专项与 tmux 产物统一无新增模型调用复评，原评分和轨迹不覆盖。

L07-eager-schema 的一请求预留 35,801、实测 36,030，累计仅 406,163/600,000，却因实际超预留停止。根因是 UTF-8 字节除以 3.5 对密集输入低估。保留首轮后，评测 Provider 改用 UTF-8 字节作保守准入估计；该值不冒充实测 Token，usage 仍是唯一结算来源。S01/S08 在 [新源码身份](calibration-v2/identity.json) 和六条新运行中复验，全部严格成功、usage 完整，不替代首轮分数。

首轮 21 次发现调用、25 次实际卸载，禁用组卸载为零，Layer2 摘要为零。基础工具、通用提示和合法替代路径保留；不删除基础能力强迫发现，也不扩大或缩小窗口制造摘要。压力审查与选择依据见 [校准决定](calibration-decisions.json)。三次 tmux 均正常退出、创建独立 Session、发生真实工具调用；两次按修订合同通过，一次仍因事实答案失败。六次新源码自动复验另列，不取最好结果。

## 预算与交付边界

[类别与正式总预算](calibrated-budgets.json) 含八个预算类别，使用全部三组失败、预算删失下界和六次复验的最大观测，乘 1.5 余量；单请求参考完整请求字节与输出上限，清理至少 20 秒。按预定冻结类别配额 ×9 再留 10% 总余量，形成 132,462 秒、352,602,222 Token、14,633 Provider/26,374 工具请求总预留，最大单请求 508,821、清理 55 秒。状态为 `CALIBRATED_NOT_FROZEN`；尚无 48 题身份或 432 行正式计划，不授权模型执行。

当前未知/缺口明确保留：一请求成本未知；推理子计数和真实账单未知；远端权重不能不可变固定；主集与复验均未触发 Layer2，不能声称摘要效果或已实测摘要成本。冻结题库、正式执行、统计和产品专项仍为后续任务。

质量门禁为完整 pytest 958 项、锁文件、Ruff/格式、增量严格 mypy/复杂度、额外新模块严格检查、架构及版本/帮助启动，均通过，见 [命令与结果](quality-results.json)。[版本](version-identity.json) 的 pyproject、运行时、锁与安装元数据均为 0.1.34。首轮与修订轮分别核对部署 wheel/源码及运行时归档指纹，保留两份产品 wheel 和所有 Provider 请求产物；交付凭据、合同、账本及归档完整性另有可执行审计。
