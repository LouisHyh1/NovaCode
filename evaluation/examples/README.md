# 第二阶段合同样例

这里的两个任务仅用于数据合同与资产校验，不属于开发或冻结题库，不是已入库题目。`single` 包含一个固定请求，`multi` 包含三个固定请求；每个任务在一个配置和重复编号下各构成一个 Evaluation Run，共两个评测运行、四个计划 Agent Run。Team Task 不参与这些计数。

运行 `uv run --locked python evaluation/examples/validate_contracts.py` 校验公开输入、初始资产、环境身份、外部验收资产及配额缺口。脚本不创建 Provider，不执行目标代码，也不生成真实运行或资格核验结果；预算类别 `example-small` 只是样例类别，没有可执行的模型预算。

`contracts/` 属于外部编排元数据，不能发送给 Agent。`public/` 是公开包，`external/` 是外部验收样例，两者的 SHA-256 在合同中固定。这里的目录分离及路径/指纹校验只证明资产管理规则，实际容器挂载隔离和初始 Git 状态核验将在第四阶段实现；不应将样例目录整体交给 Agent。样例 base commit 是初始 fixture 清单中的演示身份，不冒充已核验仓库提交。

合同以 `schema_version=1` 保存；未知字段、未知版本、重复 JSON 字段、不完整身份、无效指纹及缺失资产会被拒绝。只读任务的 `allowed_paths=[]` 表示禁止业务文件修改；`.novacode/` 状态另行处理。修改范围约束在本阶段仅校验格式，实际产物范围判定属于独立验收。

问题家族与 `problem_keys` 由 curator 审查并声明。家族检查能识别同 issue、同源修复、受控缺陷键及相同候选内容的冲突，不能自动从任意代码语义推断未声明的同源问题。`builder_id` 只记录通用构建器，不作为家族隔离依据。

`SelectionLedger` 的单写入者 JSONL 账本记录选择、入库、冻结、排除和替换，拒绝不合法转换、截断尾行及合同变化。入库要求重新校验全部任务资产和预算类别，并核对外部 `Qualification` 的合同绑定、证据指纹及资格声明；声明的真实性仍需后续各题实际核验。Live 要求原始目标失败、原有行为通过和参考连续三次通过；专项要求正确实现及负例有效。冻结题只能由已入库状态转换，之后不能排除或替换；任务冻结不等于完整 campaign 的 `FROZEN_VALID`。

替换只能出于事前资格、环境、合同、家族或配额原因，不能使用 Agent 成功/失败原因；替代题保持题集、来源、难度和主类别。每次追加前重放旧记录，再以 flush/fsync 持久化。首版不支持多个并发写入者，正文说明和 curator 审查仍需检查是否以合法原因掩盖事后结果筛选。
